# 理巢 NestTidy

Windows 上的本地目录整理工具：把 BT/PT 下载里一层套一层的空壳文件夹剥掉，让文件回到资源包根部。

当前版本 `1.7.1`。完全离线，零第三方运行时依赖，规则 `P0-R0-R5-v3`，详见 [规则对照表](docs/规则对照表.md)。想更全面地了解设计取舍，读 [详细介绍](docs/理巢_详细介绍.md)。

## 一、它做什么

下载来的资源常常长这样：

```text
电影A\百度网盘下载\解压后\正文\01.mp4
```

中间三层都没有别的文件，只是套娃。理巢把它变成：

```text
电影A\01.mp4
```

同一层级出现同名文件时，用来源文件夹名做前缀区分（`花絮-cover.jpg`、`预告-cover.jpg`），不覆盖、也不产生 `(1)` 后缀。文件最多提到资源包根部，不会被移出该包。

## 二、两种执行方式

| 方式 | 磁盘上发生什么 | 适什么时候 |
|---|---|---|
| **复制到输出目录** | 只读源目录，把整理好的副本写进你指定的输出目录。**源目录一个字节都不改**，也不删任何文件夹。空间占用翻倍，回退就是删掉输出目录。 | 第一次用、想先看结果、原目录还要留着继续做种 |
| **原地整理** | 在资源包内部移动文件（`shutil.move`），并删掉因此变空的文件夹。执行前页内确认框列出会动多少文件，写事务日志，可一键撤销。 | 确认预览没问题、想真正省掉层级 |

两个按钮都在网页上：先「试运行」看对照表，再在对照表顶部那条工具栏里选执行方式、点「确认原地整理」或「确认复制到输出目录」。原地整理执行后会给出「撤销这次整理」，按事务日志把文件挪回原处：整理时新建的文件夹会被删掉（里面还有别的东西就原样保留），这次执行的事务日志与空掉的「理巢报告」目录也一并收掉；已被删掉的空壳文件夹不重建。

关于常见疑问：**复制模式下不会「复制后删除源文件」**。源目录不被写入，唯一的代价是多占一份空间；如果你要的是省空间，选原地整理，或者整理完自己删掉旧目录。

重复副本的删除是另一个独立动作（第四步），跟整理没有关系：诊断只列候选，必须逐个勾选、二次确认才会动。

## 三、启动

需要 Python 3.11+，无第三方依赖。双击 `start_nesttidy.bat`，浏览器会打开 `http://127.0.0.1:8766`（脚本先开浏览器再起服务，命令行出现「理巢 NestTidy 已启动」后刷新一次）。也可以手动：

```powershell
python -m nesttidy.app --host 127.0.0.1 --port 8766
```

**本地配置（可省）**：程序会把「上次的源目录」和监听端口记在启动目录下的 `理巢配置.json`（和报告一样跟着启动目录走，不进被整理目录）。第一次成功试运行后文件才会出现；下次打开页面源目录自动带入。端口的取值顺序：命令行 `--port` > 配置文件 > 默认 8766。文件只有这两个字段，规则阈值、语义与排除项一律不在配置里——想改规则行为，没有入口。

## 四、整理单位

- **批量**：所选目录是存放多个资源包的父目录，其下每个子文件夹各算一个资源包。父目录里的散落文件不动。
- **单个**：所选目录本身就是一个资源包，它内部所有层级都属于它的内容。

## 五、操作流程

界面顶上是四个大页签——整理预览 / 重复文件 / 权限修复 / 诊断信息。四块彼此独立，不要求按顺序做；各自的操作按钮就在各自页签里，切过去就能用。上方那条「源目录」是所有页签共用的路径，支持粘贴、拖入文件夹（自动转成路径）和失焦即时校验。

1. 填源目录（离开输入框时会立刻告诉你路径是否存在；上一次成功用过的源目录会在打开页面时自动带入）；整理单位只影响「整理预览」。
2. 点「试运行：看看会变成什么样」——只扫描、只计算，不写磁盘。
3. 看两处：顶部摘要卡（会换位置几个、会改名几个、清掉几个空文件夹、异常几个），以及「整理前 → 整理后」逐文件对照表。路径显示为 `百度网盘 › 解压后 › 正文 › 01.mp4` 这种从浅到深的形式，「藏了 N 层」表示它现在被几层壳压着。筛选条可选「只看会变」「只看改名」「只看原地」；选前两个时，不受影响的资源包整块隐藏。筛选条、执行方式与执行按钮都固定在对照表上方，文件再多也不用拉回顶部找按钮。文件夹大到几十万个文件也别慌：每个资源包只渲染前 80 行，其余点「显示更多」按页取；扫描时进度条显示已处理的文件数（总量未知时不给假百分比）。
4. 确认无误，直接在对照表顶部那条工具栏里选执行方式并点执行。执行期间页面有进度条（已处理 / 总数 · 百分比 · 当前动作），所有按钮同时锁定防止重复点击；跑完给结果表，「原地整理」那次还多一个「撤销这次整理」，复制模式会显示输出目录并附「在资源管理器中打开」。
5. 需要留记录就点「导出报告」。「修复文件属性」同样带进度条，只列失败项，正常项只报个数。

所有等待环节（扫描、规划、导出报告、执行、撤销、修复、去重）共享一份进度契约：`GET /api/progress?key=<progress_key>` 返回 `phase / status / done / total / label / note / updated_at`。`status` 的成功与失败由服务端在响应前写入，失败时保留最后一帧并带原因；`total=0` 表示总量未知，页面显示流动条而不是假百分比。等待期间进度行常驻「请勿重复操作」，主操作按钮同时锁定。若请求本身没拿到服务端响应（断网、代理中断、服务退出），页面只提示“请求未完成”，不会把传输失败自行判成成功；能连上服务端时仍以服务端终态为准。

服务端对有持久副作用的接口（执行、导出报告、撤销、重复副本删除）再加一层防重复：执行类接口（原地整理 / 复制到输出目录）同一份试运行计划被两个标签页同时执行时，后一个请求返回 **409**（`该计划正在执行中，请勿重复提交`），不会排队、也不会生成第二份事务日志；所有这类接口对同一 `progress_key` 的重复提交同样返回 409，不会写出第二份报告或重复执行撤销 / 删除。前端按钮锁定防普通误触，服务端这层防多标签页 / 重试造成的并发。

本地接口只接受来自本机页面自己的请求：`Host` 必须是本机、带 `Origin` 的请求必须同源同端口、`POST` 只收 `application/json`。因此浏览器里别的网站没法代你点执行、删除或撤销（返回 **403**），DNS 重绑定也读不到本机接口的响应。命令行调用不受 Origin 限制，但 `POST` 要自带 JSON 头（否则返回 **415**）；页面本身一直这么发。

界面行为的三条底线（v1.4.0 起明文保证）：

- **错误永远可见**：任何页签上的失败都会出现在页面顶部的全局状态条里，不会「失败了但你看不见」。
- **计划与磁盘一致**：试运行失败会立刻作废上一份计划；执行过的计划不能再执行，按钮自动变成「重新试运行」；切换执行方式后必须重新试运行（计划是按生成时的方式冻结的）。
- **不猜你想干嘛**：空路径、不存在的路径、没勾选项的修复，都会直接告诉你哪里不对，而不是默默扫描别的目录。

## 六、重复文件诊断

页面上的「重复文件」页签。分两遍：

1. **初筛**：按所选级别比较（`fast` 大小+文件名 / `standard` 大小+首尾各 1MB / `deep` 全文件）。
2. **复核**（自动）：对每个候选组算全文件 SHA-256。哈希不一致的成员标为「复核剔除」，不会进入可删名单——这一遍专门挡住「大小相同、首尾相同、中段不同」的误判。

看到结果后逐个勾选要删的副本，每组至少留一份，再点删除：

- **移入回收站**（默认）：交给 Windows 回收站，可随时右键「还原」放回原位置；清空回收站才真正释放空间。
- **彻底删除**：立即释放空间，不可撤销，需要再确认一次。

删除前会重算待删文件与保留文件的全文哈希、核对诊断记录、检查是否越界；任一不符就跳过该条并说明原因。每删一个副本都写一条事务日志。诊断和删除过程中都有进度条；在结果表里**右键任意一行**可以在资源管理器里定位并选中那个文件，**双击预览表任意一行**打开它所在的目录。

## 七、规则与示例

规则按结构判定，不猜名字含义（「正文」「正片」没有特殊地位）。

```text
整理前                       整理后
电影A\                       电影A\
  花絮\cover.jpg      →        花絮-cover.jpg
  预告\cover.jpg               预告-cover.jpg
```

下载中文件（`.part`、`.!qb`、`.crdownload`、`.aria2`、`.tmp`、`.downloading`）保持原位，记在「异常项」里，下载完再跑一次即可。

## 八、命令行

`python -m nesttidy.app <子命令>`；不带子命令即启动网页。

| 命令 | 示例 | 参数 |
|---|---|---|
| `plan` | `plan "D:\下载\资源包"` | `--mode batch\|single`、`--output-root`、`--report-dir` |
| `copy` | `copy "D:\下载\资源包" "D:\下载\理巢输出_01"` | `--mode`、`--report-dir` |
| `move` | `move "D:\下载\资源包" --confirm` | `--mode`、`--no-elevate`、`--report-dir` |
| `undo` | `undo ".\理巢报告\task_01\transaction_log.jsonl"` | — |
| `duplicates` | `duplicates "D:\下载\资源包"` | `--level fast\|standard\|deep`、`--workers`、`--report-dir` |
| `dedupe` | `dedupe "D:\下载\资源包" --confirm` | `--level`、`--groups`、`--mode quarantine\|purge`、`--trash-dir`、`--report-dir` |
| `repair` | `repair "D:\下载\资源包"` | `--clear-readonly`、`--clear-hidden`、`--clear-zone-identifier` 等 |
| `history` | `history` | — |
| `manual` | `manual` | `--output <文件名>` |

报告写在 `理巢报告\task_年月日_时分秒\`：`summary.md`、`summary.json`、`mappings.csv`、`issues.csv`，move 另有 `transaction_log.jsonl`，dedupe 另有 `delete_log.jsonl`。以 `理巢输出_` 开头的目录会被后续扫描跳过。

## 九、常见问题

- **撤销**：`undo` 指向事务日志即可回滚 move 与 quarantine；`purge` 删除的条目无法撤销，`undo` 会逐条说明跳过原因。
- **执行失败**：看 `issues.csv` 或页面「异常项」，那里有具体原因。
- **目录互相包含**：输出目录放在待整理目录之外，否则会互相套。
- **界面显示不对 / 按钮没反应**：看页面顶部全局状态条的红字提示；所有失败（包括其他页签的）都会汇总到那里。

## 十、版本记录

- **1.7.1**（本版）：审计修复，规则语义与 `RULE_VERSION` 未变。① 权限修复三处：Windows 上勾「授权当前用户」必崩的 `icacls` 调用改正；取不到登录账户名改为逐行失败，不再中断整轮；符号链接与 junction 一律跳过，不再穿过链接改到选定目录之外的文件。② `/api/repair` 补齐 `grant_current_user` / `fix_inheritance` 转发——此前校验放行后丢弃，勾了静默不生效。③ 复制边界复查提前到 `mkdir` 之前：链接逃逸被拒时，输出根之外不再留下空目录。④ 本地接口增加请求来源防线（Host 白名单 + Origin 同源 + POST 只收 JSON），挡跨站代点与 DNS 重绑定。⑤ 进度槽写入加锁，淘汰改为优先清已完成键，与执行锁的幂等口径一致。⑥ 非 Windows 上「移入回收站」改为逐行失败并说明原因，不再整批中断，也不会降级成直接删除。⑦ 复制方式未填输出目录时，试运行前就提示。⑧ `--host` 非本机改为一行报错，不再抛 traceback。新增 `tests/test_repair_seams.py`、`tests/test_web_request_guard.py` 等 18 例。
- **1.7.0**：性能与并发三项。① `os.scandir` 复用枚举元数据，减少 `build_tree` / `resource_roots` / `snapshot_digest` 每文件重复 `stat`；② `resolve()` 改为单次规划内记忆化（键为原始路径字符串，resolved 语义不变）；两项均有「改造前后计划逐字节一致 + 变异测试」证明，规则与 `RULE_VERSION` 未变。③ 服务端 `per-plan` 执行锁 + `progress_key` 幂等：同一计划并发执行第二个请求返回 409，同一进度键重复提交不产生第二份事务日志 / 报告。本地 2 万文件剖析显示主要耗时在规则处理而非目录枚举，故并行扫描（P1-1）暂不启动，待 Windows 10 万文件实测再议。
