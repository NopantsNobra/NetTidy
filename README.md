# 理巢 NestTidy

**【现行】** 产品说明。规则语义以 `docs/规则对照表.md` 为准，执行规范见 `AGENTS.md`，路线见 `ROADMAP.md`。

## 1. 产品概述

理巢是一款在本地计算机运行的离线目录整理工具，只做一件事：剥掉资源包里多余的空壳文件夹，把散在深层目录中的文件提到资源包内合适的位置。

大量 BT/PT 下载内容往往文件夹一层套一层，结构不规则、难以整理。理巢通过自动化减少嵌套层级，提升目录浏览与内容查阅效率。主要面向 P2P 玩家、BTer/PTer、电子仓鼠等下载量大、目录层级复杂、需要快速掌握内容的用户群体。

## 2. 安全边界

- **不删除文件。** 整理过程中清除的仅是文件被提走后变空的文件夹。
- **不静默覆盖。** 目标位置已存在同名文件时，工具会停止并报错，而不是覆盖。
- **不联网。** Web 界面仅绑定本机 `127.0.0.1`，不接受外部连接，也不向外发送数据。
- **不自动执行。** 生成预览只计算整理计划；未触发执行前，磁盘不会发生任何变更。
- **撞名不使用数字后缀。** 同名文件以来源文件夹名作为前缀区分，例如 `花絮-cover.jpg`，不会生成 `cover (1).jpg`。
- **仅支持 Windows**，面向单机单人场景，无账号体系、无云同步。

此外，理巢不判断文件夹名称的语义（「正文」「正片」等不作特殊处理），也不会自动删除重复文件。文件最多提升至所属资源包的根目录，不会被移出该资源包。

## 3. 启动方式

运行前需安装 Python 3.11 或更高版本，无需安装额外的库。双击 `start_nesttidy.bat` 后，浏览器会自动打开 `http://127.0.0.1:8766`。

批处理脚本先打开浏览器、再启动服务，因此首次访问可能暂时无法连接；待命令行窗口出现「理巢 NestTidy 已启动」后刷新页面即可。若出现「启动失败」提示，通常表示 Python 未正确安装。另一种方式是在项目目录打开命令行执行：

```powershell
python -m nesttidy.app --host 127.0.0.1 --port 8766
```

随后访问 `http://127.0.0.1:8766`。

## 4. 整理模式

模式选择取决于待整理目录的层级：整理对象是「包含多个资源包的父目录」，还是「单个资源包」。

### 批量整理

选择**包含多个资源包的父目录**：

```text
D:\下载\资源包\
  电影A\
    百度网盘下载\解压后\正文\01.mp4
  电影B\
    解压后\正片\movie.mkv
```

其下每个子文件夹各作为一个资源包分别整理。父目录本身不参与整理，散落在父目录中的文件保持原位。**判定依据：所选目录为存放资源包的上层目录时，使用批量整理。**

### 单个资源整理

选择**资源包本身**：

```text
D:\下载\资源包\电影A\
  百度网盘下载\解压后\正文\01.mp4
```

该文件夹即为待整理对象，其内部所有层级都属于它的内容。**判定依据：所选目录本身即为资源包时，使用单个资源整理。**

## 5. 标准操作流程

1. 在「源目录」填写待整理目录的路径。
2. 在「整理模式」选择批量整理或单个资源整理（依据第 4 节）。
3. 点击「生成试运行计划」。
4. 查看两张表：「预览映射」列出每个文件的原位置与计划目标位置；「异常项」列出跳过或出现问题的条目及原因。
5. 确认计划无误后，选择第 6 节的执行方式。

**预览阶段不写入磁盘**，仅列出计划中的操作，文件不会被移动或复制。需要留存记录时，可点击「导出报告」。

## 6. 执行方式

### 安全复制（copy）：建议首次使用

网页上的「执行安全复制」对应此方式。在「copy 输出目录」指定位置后，理巢会把整理后的**完整副本**写入该目录，源目录保持不变。如需回退，删除输出目录即可恢复原状。适用于首次试用或需要保留原始目录的场景。输出目录应位于待整理目录之外，避免目录互相包含。

### 直接整理（move）：确认无误后使用

该方式直接整理源目录，不另存副本；必须显式确认才会执行，并生成事务日志供事后撤销。命令行中需附加 `--confirm`，详见第 9 节。

**网页界面仅提供「执行安全复制」，没有 move 按钮；move 只能通过命令行执行。**

### 目录与报告

- **报告目录**固定命名为 `理巢报告`，位于启动理巢时的工作目录（双击批处理脚本时为脚本所在目录）。每次任务默认单独创建 `task_年月日_时分秒` 子目录；命令行可通过 `--report-dir` 指定其他位置。
- **输出目录**名称可自定义，建议使用 `理巢输出_20260514_2130` 形式。以 `理巢输出_` 开头的目录会在后续扫描中被自动跳过，不会被误识别为资源包。

报告目录包含 `summary.md`（摘要）、`summary.json`（同数据的 JSON 形式）、`mappings.csv`（预览映射表）与 `issues.csv`（跳过、失败及问题条目，执行失败也记录于此）。通过**命令行**执行重复文件诊断时，报告目录会额外生成 `duplicate_report.csv`（网页端诊断仅在页面展示，不写入文件）；执行 move 时会生成 `transaction_log.jsonl`，作为撤销依据。

网页端执行完成后，需点击「导出报告」，报告才会写入磁盘。

## 7. 整理结果示例

**示例一：剥掉空壳**

```text
整理前：
电影A\
  百度网盘下载\
    解压后\
      正文\
        01.mp4

整理后：
电影A\
  01.mp4
```

中间几层只包含下级文件夹、自身不含文件，因此被剥除。`正文` 这一名称不会被特意保留——理巢依据结构判断，不依据名称语义。

**示例二：同名文件**

```text
整理前：
电影A\
  花絮\
    cover.jpg
  预告\
    cover.jpg

整理后：
电影A\
  花絮-cover.jpg
  预告-cover.jpg
```

两个 `cover.jpg` 被提升至同一层级后，分别加上原所在文件夹名作为前缀，彼此不覆盖，也不会出现 `cover (1).jpg`。

## 8. 常见问题

**下载未完成的文件**：以 `.part`、`.!qb`、`.crdownload`、`.aria2`、`.tmp`、`.downloading` 结尾的文件会被跳过、保持原位，并在「异常项」中记录。下载完成后重新运行一次即可。

**「正文」「正片」等名称**：理巢不推断名称含义，只依据文件夹内是否含文件、嵌套层级判断；符合剥除条件的照常剥除，符合保留条件的照常保留。

**执行失败的排查**：报告中的 `issues.csv` 与网页「异常项」列出具体条目及原因，整体数量见 `summary.md`。

**撤销整理**：使用 move 后，可用命令行 `undo` 指向报告中的 `transaction_log.jsonl`，将已移动的文件放回原处。已被清除的空文件夹不会自动重建。使用 copy 时源目录从未改动，删除输出目录即可恢复原状。

**重复文件处理**：诊断仅生成报告，网页端展示于「诊断 / 历史」区，命令行生成 `duplicate_report.csv`。是否删除由使用者自行决定。

## 9. 命令行速查

命令形式为 `python -m nesttidy.app <子命令>`；不带子命令时启动网页界面（`--host` 默认 `127.0.0.1`，`--port` 默认 `8766`）。

| 命令 | 示例 | 可选参数 |
|---|---|---|
| `plan` | `plan "D:\下载\资源包"`（生成预览，不写磁盘） | `--mode batch\|single`（默认 `batch`）、`--output-root <目录>`、`--report-dir <目录>` |
| `copy` | `copy "D:\下载\资源包" "D:\下载\理巢输出_20260514_2130"` | `--mode`、`--report-dir` |
| `move` | `move "D:\下载\资源包" --confirm`（`--confirm` 必须附加） | `--mode`、`--no-elevate`、`--report-dir` |
| `undo` | `undo ".\理巢报告\task_20260514_213000\transaction_log.jsonl"` | 无 |
| `duplicates` | `duplicates "D:\下载\资源包"` | `--level fast\|standard\|deep`（默认 `standard`）、`--workers <数>`（默认 `4`）、`--report-dir` |
| `repair` | `repair "D:\下载\资源包"`（默认不修任何项） | `--clear-readonly`、`--clear-hidden`、`--clear-zone-identifier`、`--grant-current-user`、`--fix-inheritance` |
| `history` | `history` | 无 |
| `manual` | `manual` | `--output <文件名>`，默认 `理巢_NestTidy_简要操作手册.pdf` |

## 附录：维护者信息（一般使用者可跳过）

### 复算口径

规模与用例数一律现算，不写死数字：

- 用例数用 `grep -h "def test_" tests/*.py | wc -l` 复算，Windows 上必须全绿。POSIX 通过不算通过——历史上两个只在 Windows 暴露的缺陷就是这么漏掉的。
- 模块数 / 源码行数用 `ls nesttidy/*.py | wc -l`、`wc -l nesttidy/*.py` 复算；附注标签数用 `git tag | wc -l` 复算，与版本脉络逐行对应。
- 跑全套：`python -m unittest discover -s tests`。

用例全绿只说明「已写断言成立」，不说明产品正确：先有真实目录复现，再补断言，顺序不能反。项目结构与文档用途见 `AGENTS.md`、`docs/规则对照表.md`、`docs/理巢_产品开发手册_v1.0.md`。

### 版本脉络（压缩保留）

项目跨两代产品线，中间推翻重来四次：第一代是「文件夹整理工具」，第二代更名重写为理巢 NestTidy，引入边界保护后定型，之后是规范化与规则修正。逐版本的时间、实质与规模表不再重印，需要时可通过 `git tag` 查询，完整脉络见 `ROADMAP.md` 与 `docs/history/项目脉络分析_2026-10-23.md`。

### 常用版本管理操作

```bash
git checkout v5.3                            # 切换到任意历史版本，只读查看
git diff v8.0 v9.0 --stat                   # 查看两次重构的差异
git ls-tree -r --name-only v7.5             # 列出某版本的全部文件
git log --graph --oneline --all --decorate # 时间轴
git checkout main                           # 回到最新
```

切换到历史版本后如需改动，先建分支：`git switch -c explore/v5.3 v5.3`；直接 commit 会进入 detached HEAD，改动容易丢。

### 历史重建说明

现有提交并非开发当时的原始提交记录：项目曾以 zip 存档封存，未使用版本控制，后续从存档重建了完整历史。判断可靠性时需留意以下口径：每个标签保存的是该版本当时的全部文件；提交时间采用版本的诞生时间（存档内最早文件时间戳），而非真实提交时间；文件时间戳多处存在复制覆盖，顺序按语义排列，不按时间戳排列；缓存、压缩副本、编译产物和历史数据库已排除，目录内并存的多个代码副本按原样保留。判断依据来自 `docs/history/项目脉络分析_2026-10-23.md` 与源码核对。
