## 目标

维护和发展理巢：只跑 Windows 本机、不联网、单人使用的文件夹结构整理工具。它只做一件事——剥掉资源包里的空壳目录，把散落在深层的文件提到资源根内合适的位置，撞名用溯源前缀。产品价值全部集中在 P0–R5 七条规则的可信性上；当前阶段是把已有规则钉死，不扩功能面。使用对象是 BT/PT 下载量大的单机用户（资源包剥壳），不是已安装软件目录的整理（实测证明场景错配，见「可采用的假设」）。

- 治理文档预算：`AGENTS.md + ROADMAP.md + docs/规则对照表.md` 合计 ≤600 行（当前 573）。产品文档只许 2 份（手册 + README）。
- 远端：`git@github.com:NopantsNobra/NetTidy.git`（私有，SSH-over-443 间歇故障属已知环境现象）。推送链路按 `AGENTS.md` 6.2 第 6 条：先 fetch 查分叉，push 后 ls-remote 核对 + 干净克隆复跑。

**必须保持兼容的行为**

- CLI 子命令与参数（`plan` / `copy` / `move` / `undo` / `duplicates` / `repair` / `history` / `manual`，`--confirm` 强制、`--report-dir` 等）；报告产物命名与格式（`summary.md` / `summary.json` / `mappings.csv` / `issues.csv` / `transaction_log.jsonl`）；`plan_id` 索引的冻结计划（多标签页各执行各的）；move 事务日志可撤销；`理巢输出_` 前缀目录自动跳过；默认端口 8766 与 `NESTTIDY_PORT` 环境变量。

**禁止修改的范围**

- `rules.py` 的规则语义（P0–R5 冻结；改动必须同时升 `RULE_VERSION` + 改对照表 + 先写能复现旧行为错误的测试 + 记 ROADMAP，缺一不算改完）；九条安全不变量；「已知不做」清单（联网/云同步/账号/协作/语义猜目录/自动删重复/数字后缀撞名/跨平台宣传等）；目录名语义判断——这是产品立身之本。

**可采用的假设及验证方式**

- 「计划只读」：planner 不写磁盘，有 `PlannerReadOnlyTests` 背书，可在任何真实目录上安全 dry run（报告写独立目录）。
- 「执行层边界可信」：`ensure_target_within_output` 用真实路径解析拦截越界，junction 实测拦截；展示层词法归一化的盲区已披露，不构成安全缺口。
- 「打包后行为未验证」：PyInstaller 形态的长路径/ADS/出站尚未复验，任何涉及 EXE 的假设必须先实测，不得沿用源码形态的结论。

## 独立验收标准

- [ ] 给定干净 Windows 环境，执行 `python -m unittest discover -s tests`，应得到全部用例通过（数量现算），且未删除/跳过/放宽任何既有断言。
- [ ] 给定任意真实目录，执行 `plan`（dry run），应得到冻结计划与报告，且源目录文件数、目录数、内容前后一致（唯一允许的落盘是报告目录）。
- [ ] 原故障回归——以下场景必须保持既有防护，任何改动后逐一复验：端口被普通占用或 SO_REUSEADDR 占用 → 退出码 23 + 明确中文提示（`test_web_plans.py::PortBindingTests`）；资源根为盘根 → 不产生假越界（`test_mvp4.py::ReportDisplayTests`）；深嵌套目录规划保持集合查表路径，不回退 O(目录×文件)（`test_invariants.py::PlannerResidualDirEquivalenceTests`，含与旧实现逐字段比对）。
- [ ] 既有行为不回归：copy 交出完整副本、计划与执行模式一致、失败入报告、undo 覆盖 move、多线程结果一致（九条不变量对应测试全绿）。
- [ ] 治理文档三文件合计 ≤600 行（现算），源码 ≤3000 行、单文件 ≤400 行、模块 ≤20（现算）。

## 决策权限

- **可自主执行**：读取仓库任意文件；局部修改源码/测试/文档；在系统临时目录生成产物；对任意真实目录跑只读 `plan`；运行测试与本地检查；设置 GitHub 仓库元数据（description/topics）。
- **需要先确认**：改动规则语义或 `RULE_VERSION`；变更公共契约（CLI 参数、报告格式、端口约定）；`git push` 与打标签；启动 EXE 封装；引入任何第三方包；把功能扩展到产品定位之外（如程序目录整理）；对源目录执行 `copy` / `move` / 任何写操作。

## 验证与交付

每次改动按 `AGENTS.md` 6.2 六条完成前检查执行，并按第 10 节工程协作约定报告：

1. 修改的文件及原因（每处可指认）；
2. 实际执行的检查与结果（测试数量、dry run 对照数字、行数复算，标注口径与日期）；
3. 未验证项及验证方法（查不到就写「未查证」，禁止用看似合理的数字填空）;
4. 剩余风险或后续约束加固建议（发现转测试，或显式豁免记入 ROADMAP 风险台账）。

事实、价格、政策、数据必须有来源；引用数据标注口径与时间；区分「事实」「推断」「需自行核实」三层，不混写。
