### 配套：目录删除登记（v2 起为硬约束）

**执行后必然为空的目录，必须出现在计划的 `rmdir` 里。** 判定是结果导向的：计划跑完后，若没有任何目标路径落在某个原始目录内，该目录就是空的。

不按「哪条规则负责删」逐条登记——R0/R1/R2/R3/R4 都会产生空目录，逐条登记必然漏（v1 就漏了 R1/R2）。由 `planner.build_plan()` 统一判定，规则函数只管结构不管删除。

测试：`test_move_execution_leaves_no_shell_dirs`（端到端，磁盘不得残留壳）、`test_rmdir_refuses_non_empty_dir_without_claiming_success`（非空不得谎报成功）。

**v1.8.0 起补 R6 兜底**：上面是**规划期**判定（计划里写死的 `rmdir`）。执行期还会变空——计划冻结后另一个程序删掉/搬走了目录里唯一的文件，或用户在执行前手工清过。这类目录不在计划里，由 `executor.sweep_empty_dirs()` 在 move 收尾时统一收掉，逐条写 `rmdir` 事务行；**整理后为空的资源根同样删除**（选中根除外）。撤销时 `rmdir` 行会重建目录，因此清扫是可还原的。测试：`test_empty_shell_sweep.py`（六条：清扫生效 / 空资源根被删 / 选中根保留 / 事务行落盘 / 撤销重建中间目录 / 撤销重建资源根）。

### 配套：重复副本删除的前置校验（v0.6.0）

**去重是唯一会删文件的能力，因此校验写在删除路径上，而不写在诊断结果里。** 诊断给的「可删候选」只是一份建议，`executor.delete_duplicates()` 在落任何一次删除/隔离之前，对每个候选按固定顺序复核，任一不满足即 `skip` 并写入报告，不改动磁盘：

| 序 | 校验 | 失败码 | 为什么这一条不能省 |
|---:|---|---|---|
| 1 | 保留项不能就是被删项本身 | `KEEP_IS_VICTIM` | UI 之外还应有结构防线 |
| 2 | 候选必须落在 `selected_root` 之内（`resolve()` 后比对，拒符号链接/junction） | `OUT_OF_ROOT` / `SYMLINK_REFUSED` | 与 P0 同源：越界即不受信任 |
| 3 | 保留项与候选本身都必须还在 | `KEEP_MISSING` / `SOURCE_MISSING` | 诊断到删除之间用户可能已手动挪动 |
| 4 | 候选与保留项不是同一个文件（含硬链接判定） | `SAME_FILE` | 硬链接会「删一个等于删两个」 |
| 5 | 候选与保留项的**全文件 SHA-256 必须相等** | `NOT_DUPLICATE` | 这是第二遍复核的最终落地口径 |
| 6 | 候选的当前哈希等于诊断时记录的哈希 | `CONTENT_CHANGED` | 诊断后被改写过的文件不算重复 |

删除方式两档：`recycle`（默认，`SHFileOperationW` + `FOF_ALLOWUNDO` 交给 Windows 回收站，用户从回收站还原）与 `purge`（`unlink`，需 `confirm=true`，不可撤销）。每次处理都写一条独立 tx 记录，动作名 `recycle` / `delete`；`quarantine` 作为旧名别名仍被接受。

测试：`tests/test_readability_and_dedupe.py` 的 `DeleteDuplicateTests`（保留项缺失、内容被改、越界、硬链接、purge 缺 confirm、quarantine 可再生回）与 `TwoPhaseDuplicateTests`（复核剔除、`--no-verify` 标记）。

两阶段比对：第一遍按 `fast`（大小 + 文件名）/ `standard`（大小 + 首尾各 1MB 哈希）/ `deep`（全文件 SHA-256）分簇，第二遍对每一簇自动做全文件 SHA-256 复核。**判定是「最大哈希组必须 ≥2 个成员」**——只剩 1 个即初筛误判，整簇 `verified=false`、组 id 加 `-recheck`、`conflict_note` 写「首尾相同但全文哈希不同」，**永不进可删集合**；`deep` 第一遍已全量，跳过第二遍但直接 `verified=true`。
