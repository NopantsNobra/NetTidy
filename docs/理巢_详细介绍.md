# 理巢 NestTidy · 详细介绍

适用版本：1.11.0 · 规则版本：`P0-R0-R5-R6-v5` · 更新：2026-11-24

[中文使用说明](../README.md) | [English README](../README.en.md)

## 产品定位

理巢不是通用文件管理器，而是面向 BT/PT、网盘下载和反复解压所产生的嵌套目录的本地结构整理工作台。它解决三个具体问题：冗余层级、同名冲突、重复副本。目录结构规则确定且可解释，不根据内容或文件夹名字猜测用户意图。针对 Windows 文件属性和下载标记提供独立修复能力。

## 为什么先预览再执行

整理正确性来自规划与执行的分离。扫描源目录生成虚拟树，按固定结构规则计算目标路径、操作、映射、异常及快照摘要；冻结计划按 ID 保留在服务端。网页展示「现在在哪 → 整理后在哪 → 动作 → 原因」，由用户确认后引用该计划执行。复制模式不写源目录，支持对同一输出目录重新规划后续跑，完整签名与状态一致的已有副本跳过，其他冲突拒绝覆盖；原地整理按计划移动，并清理确认为空的目录。R6 在执行收尾处理新变空的目录，含空资源包，但保留选中根。

执行层不把预览当作磁盘状态的永久保证：写入前复查源状态、资源根身份、目标冲突与链接边界；事务意图先记录再执行。撤销按日志逆向恢复，安全条件不满足时保留日志及失败原因。R6 清理目录可按有效事务记录重建，不是旧版所说的「空目录不重建」。恢复机制不等于 ACID 或备份。

去重为独立诊断与删除流程。初筛后用全文签名分组，所有至少两个成员的真实子组独立保留；删除前重新验证待删与保留项及边界、签名、硬链接状态。默认 Windows 回收站，永久删除不可撤销。

## 界面与性能设计

网页为四页签工作台，源目录共享。进度反馈在未知总量时不伪造百分比；错误统一显示，危险确认默认聚焦取消，支持键盘与窄屏操作。先选择执行方式再试运行，模式变化或已执行的计划需重新生成。

早期只限制滚动窗口，仍创建较多 DOM。现行整理预览采用轻量摘要、服务端分页索引、完整条件筛选、每包固定 80 行；资源包选择器分段并支持跳转。重复诊断按组分页、跨页勾选与已加载全选；当前仍受 400 条明细传输上限约束。空目录、异常、执行、撤销、修复和历史均使用有界结果表格。前端 DOM 有界不代表所有后端数据、网络传输和浏览器内存均已完全分页。

在后端，普通 Windows 枚举元数据复用、单次规划路径解析缓存、祖先闭包短路、紧凑对象、进度节流与计划缓存预算降低了重复工作。默认预算 60 万条目，典型 20 万文件计划保留一份；运行中计划不得淘汰。拒绝了存在短文件名及链接反例的父目录路径投影，也未引入仅有微小收益的扫描并行。性能数据及未完成验收统一见 [README](../README.md#大规模性能) 和 [ROADMAP](../ROADMAP.md)，不在本文另设重复台账。

## 架构

```text
Web 工作台 (ui.py) / CLI (app.py)
             |
    web.py：本地 HTTP、计划缓存、并发保护
             |
    planner.py + rules.py：只读扫描与冻结计划
             |
    executor.py + recovery.py：执行与恢复
             |
    duplicate.py / repair.py / reports.py：专项能力
```

| 模块 | 职责 |
| --- | --- |
| rules.py / planner.py | 结构规则、虚拟树、边界、计划与快照 |
| executor.py / recovery.py | 副作用前复核、事务日志、撤销与安全失败 |
| duplicate.py / repair.py | 两阶段去重、Windows 属性及权限修复 |
| reports.py | 摘要、分页派生、完整计划报告 |
| web.py / ui.py | 标准库 HTTP 服务、生命周期、原生 HTML/CSS/JS 工作台 |
| app.py / config.py | CLI、启动及最小本地配置 |
| tests/ / benchmarks/ | 单元与行为回归、隔离性能夹具、浏览器压力验证 |

无第三方运行时依赖、无前端构建、无云端处理。现行产品仍以 Windows 与源码启动为主；英文 README 不代表界面已国际化，MIT 许可已确定，首个 EXE 已构建但尚未完成分发验收。
