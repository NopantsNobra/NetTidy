# 理巢 NestTidy 详细介绍

**版本**：1.5.0 ｜ **规则版本**：`P0-R0-R5-v3`（本文件不定义规则语义；规则的唯一权威来源是 [规则对照表](规则对照表.md)，冲突时以它为准）
**适用读者**：想判断「这个工具值不值得用、设计靠不靠谱」的人，以及未来的维护者。

---

## 1. 一句话与一段话

**一句话**：把「电影A\百度网盘下载\解压后\正文\01.mp4」变成「电影A\01.mp4」，在你看清楚每一步之前不碰磁盘。

**一段话**：理巢面向 BT/PT 下载目录的「套娃空壳」问题——下载资源常被网盘导出、多层解压、发行组打包包出三四层只包着一个文件的目录。它按七条结构规则（P0 边界、R0–R5 剥壳）生成一份**只读计划**，用「现在在哪 → 整理后在哪 → 为什么要这样」的对照表交给你过目，然后才提供两种执行方式：复制到输出目录（源目录一字节不改）或原地整理（带事务日志、可撤销）。它还附带两阶段重复文件诊断（初筛 + 全文件哈希复核，点选式删除，默认进回收站）和权限修复。全程离线，零第三方运行时依赖，绑定 127.0.0.1。

## 2. 为什么是「先看计划，再动磁盘」

同类整理工具最大的信任成本是「它到底会把我文件挪成什么样」。理巢把回答拆成三层：

1. **冻结计划**：试运行生成计划后即刻冻结（`OperationPlan.frozen`），服务端按 `plan_id` 存放（`PlanRegistry`，最多 16 份、LRU 淘汰），前端只回传 id 不回传计划对象——你确认执行的就是你看到的那份，不存在「确认时计划又变了」。
2. **可解释的对照表**：每个文件一行，四列关键信息：现在在哪（`百度网盘 › 解压后 › 正文 › 01.mp4`，「藏了 4 层」）、整理后在哪、动作（移动到 / 改名 / 原地不动）、**为什么要这样**（规则的白话解释，如「上层目录只包着一个子目录，合并掉这一层」）。你可以逐行核对，双击在资源管理器里打开那一行所在的目录。
3. **执行层复核**：计划正确不等于执行时磁盘还是那个样子。执行器对每个操作落盘前重新检查：源文件还在吗、被改过吗、目标位置有冲突吗、有没有跑到资源包边界之外。任何一项不符就跳过并写进异常项，绝不含糊通过。

去重是全产品唯一删文件的能力，所以校验直接写在删除路径上（而不是诊断结果里）：删之前重算待删与保留文件的**全文件哈希**、比对诊断时记录的哈希、确认待删文件在选定范围内、确认不是同一物理文件（硬链接）、确认不是符号链接。六项全过才动一个字节。

## 3. 七条规则速览（语义以规则对照表为准）

| 规则 | 一句话语义 |
|---|---|
| P0 | 文件最高只提升到资源包根部，永不移出该包；理巢自己的报告/输出/隔离目录永远跳过 |
| R0 | 真空的目录（含子树全空）登记删除 |
| R1 | 直链穿透：root 下只有一条文件链时整条穿透（穿透后仍须跑 R0–R4，不短路） |
| R2 | 壳吸收：只包着一个子目录的层，合并掉 |
| R3 | 分叉口：出现多个子项的层级是语义边界，不再上提 |
| R4 | 单文件提级：目录里只剩一个文件时，提到上一层 |
| R5 | 撞名处理：用来源目录名做前缀（`花絮-cover.jpg`），前缀无法区分时用路径短码兜底，绝不覆盖、绝不产生 `(1)` 后缀 |

规则按**结构**判定，不猜名字含义——「正文」「正片」这些词没有特殊地位，这是它和「智能清理」类工具的根本区别。

## 4. 安全边界清单

- 只绑定 `127.0.0.1`；服务端拒绝其他 host；端口占用时给出明确的中文错误（并特意关闭 `SO_REUSEADDR`，避免 Windows 上与同为 reuse 的占用方静默共存）。
- 复制模式不写源目录；原地整理每个移动写事务日志，`undo` 按日志逆向还原（被清掉的空壳文件夹不重建）。
- 重复副本默认进 Windows 回收站（可在回收站还原）；彻底删除需显式选择 + 再次确认。
- 下载中文件（`.part` `.!qb` `.crdownload` `.aria2` `.tmp` `.downloading`）不动，记入异常项。
- 符号链接、目录联接（junction）、系统文件一律不跟随不处理。
- 报告/输出/隔离目录以固定前缀命名并从扫描中排除，理巢永远不会整理自己的产物。

## 5. 界面设计的三条底线（1.4.0 起）

这一版修订不动规则，动的是「状态与反馈的可信度」：

1. **错误永远可见**。全局状态条固定在页签下方，任何页签、任何一步的失败都以红字汇总到那里——旧版本里其他页签的失败写在隐藏面板中，用户什么都看不到。
2. **页面语言与磁盘事实一致**。试运行失败立刻作废旧计划（旧版会保留上一份计划且仍可执行）；执行过的计划不能再执行，按钮自动变成「重新试运行」；切换执行方式后执行按钮禁用并提示重新试运行——因为计划是按生成时的方式（含输出目录）冻结的。
3. **不猜用户意图**。空路径、不存在的路径、没勾任何项的修复，直接报错说明，而不是静默扫描服务器当前目录（旧版空路径会落到进程 CWD，等于扫描理巢程序自己所在的文件夹）。

配套的易用性改动：源目录输入失焦即时校验（✓ 目录存在 / ✗ 目录不存在）、支持从资源管理器拖入文件夹、自动去引号；主操作执行期间所有按钮锁定防重入；原生 confirm/alert 换成页内模态；下拉选项缩短为短语、长说明放提示行；重复文件表「文件」列只显示文件名（完整路径移入悬停提示）；窄屏不再横向溢出（<900px 单列布局，<700px 页签 2×2）；页签支持键盘操作（Tab 聚焦、Enter/方向键切换）。

## 6. 技术形态与取舍

- **形态**：Python 标准库 `ThreadingHTTPServer` + 单文件内联 HTML/CSS/JS（`nesttidy/ui.py`），数据全部走 `/api/*` JSON。无框架、无构建步骤、无第三方运行时依赖——`pip install` 都不需要，克隆即用。
- **CLI 与网页平行**：同一套 planner/executor 核心，两种入口。网页承担交互与确认，CLI 承担自动化（`--confirm` 语义与网页的确认框一一对应）。
- **测试纪律**：规则修改必须「代码 + 规则对照表 + 测试」三者同步，缺一不算修改。测试套件 202 例（用 `grep -h "def test_" tests/*.py | wc -l` 复算），覆盖规则语义、执行边界（越界拦截、junction 逃逸拒绝）、撤销闭环、两阶段去重的误判剔除、本地配置的读写与启动优先级、执行锁与幂等、以及界面结构契约（sticky 工具栏、滚动容器、全局状态条位置）。
- **最小本地配置**：`理巢配置.json` 落在启动目录，只记上次的源目录与监听端口两个字段；规则阈值、语义、排除项刻意不开放配置。
- **明确的「不做」清单**（见 ROADMAP）：不联网、不遥测、不做语义猜目录、不做无人确认的自动删重、不加插件系统、不做跨平台宣传。功能面收敛是刻意的——这个产品的价值全部集中在七条规则的可信度上。

## 7. 目录结构

```text
nesttidy/
  rules.py      七条规则的纯函数实现（无 I/O，可独立测试）
  planner.py    规划器：规则 → 冻结计划（含边界校验、快照摘要）
  executor.py   执行器：逐操作复核 + 事务日志 + 回收站删除
  duplicate.py  两阶段重复检测（初筛 + SHA-256 复核）
  recovery.py   undo：按事务日志逆向还原
  repair.py     权限修复（icacls / 属性 / Zone.Identifier）
  reports.py    报告导出（summary/mappings/issues/边界检查）
  web.py        HTTP 服务与 /api/* 路由
  ui.py         单文件页面（本版重点修订）
  app.py        CLI 入口与启动
docs/
  规则对照表.md            规则语义唯一权威来源
  理巢_产品开发手册_v1.0.md  产品手册
  理巢_详细介绍.md          本文件
tests/          202 例测试
```

## 8. 上手路径

1. 双击 `start_nesttidy.bat`（需 Python 3.11+）。
2. 粘贴或拖入下载目录，点「试运行」；上一次成功用过的目录会在打开页面时自动带入。
3. 看摘要卡与对照表；有疑问就双击某一行去资源管理器里亲眼核对。
4. 第一次用建议选「复制到输出目录」，比对满意后再对别的目录用「原地整理」。
5. 重复文件与权限修复是独立页签，需要时再用；诊断信息页签看异常项、规则命中统计和边界检查。

更细的操作细节见 `docs/理巢_产品开发手册_v1.0.md`；命令行用法见 README 第八节。
