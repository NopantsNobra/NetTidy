《文件夹结构智能重组引擎 - 产品与技术规范手册 V2.0》
1. 产品定位与设计哲学

本产品定位为工业级的本地/网络文件系统结构重组引擎。
设计哲学为：“绝对防丢、极度容错、底层穿透”。在任何极端的文件畸形、权限缺失、网络断连情况下，引擎绝不允许发生静默数据覆盖或主线程崩溃，必须做到单点故障隔离。
2. 核心架构约束（开发红线）
2.1 数据驱动与解耦

    统一数据载体：全链路传递 FileNode 结构体（包含路径、大小、层级、isSymlink、isLocked 等元数据），严禁模块间直接传递纯字符串路径。
    管道与过滤器模式：诊断模块只产出 List<FileNode>，各业务模块（清理/扁平/重组）在内存中对列表进行增删改（如修改 targetPath 字段），底层统一 IO 执行器 只负责最后根据列表执行物理操作。杜绝跨模块直接调用方法。

2.2 错误隔离机制

    ErrorCollector 模式：任何批处理任务启动时实例化错误收集器。单文件操作必须包裹在 try-catch 中，异常仅入栈 Collector 并执行 continue，绝对禁止抛出到主线程。
    目录级阻断日志：遇到无权限目录，立即停止递归该目录，仅记录一条 Error：“无权限访问目录 X，已跳过其包含的所有子项”，防止产生数万条无意义的子文件报错日志。

3. 业务功能模块规范
模块一：结构诊断引擎

    功能 1.1：多维清单导出。输出 CSV/JSON，包含：完整路径、文件名、扩展名、大小(MB)、层级深度、是否为重解析点(符号链接)。
    功能 1.2：深层统计。支持分析出“层级最深的前 N 个文件”、“体积最大的 N 个目录”，为后续清理提供依据。

模块二：智能剔除引擎

    功能 2.1：规则化缓存清理。基于内置字典（temp, node_modules, __pycache__ 等）精准匹配文件夹，整体移入回收站或直接删除。
    功能 2.2：哈希级去重。计算文件 MD5/SHA1，按策略（保留最浅层级/最新修改时间）标记待删除项。禁用直接覆盖，同名冲突项强制重命名保留。

模块三：层级扁平化引擎

    功能 3.1：按规则强制提取。输入扩展名列表或正则表达式，将散落在深层的文件剪切至指定单层目录。
    冲突解决硬性逻辑：遇到同名文件，自动追加后缀（如 _1, _from_parentdir）。系统隐藏文件（desktop.ini, Thumbs.db）强制过滤，不参与提取。

模块四：结构重组引擎

    功能 4.1：单级提级。将选中文件夹内的所有直属子项移动到其父目录，随后删除空壳。
    功能 4.2：智能解包。自动识别并合并“文件夹名与其内部唯一子文件夹名完全相同”的冗余结构（如 A/A/文件 变为 A/文件）。
    冲突降级处理：提级时若父级已存在同名项，不弹窗阻塞队列，将该冲突项移入名为 _冲突合并_时间戳 的临时缓冲目录，待整体任务结束后交由用户人工裁决。

模块五：收尾与校验引擎

    功能 5.1：倒序空目录清理。从最深层级向上遍历，仅当目录内文件数为 0 时删除，无视隐藏属性。
    功能 5.2：非法字符净化。提供正则替换，批量剔除文件名中的 \ / : * ? " < > | 及首尾空格。

4. 底层文件系统引擎规范 (The “Deep Pit” Killers)

*此部分为系统级 API 调用规范，用于对抗 Windows 文件系统的畸形场景。*
4.1 超长路径 穿透

    全局前缀策略：引擎底层初始化时，对所有传入路径强制重写。本地路径加上 \\?\（如 \\?\C:\Users\...），网络路径加上 \\?\UNC\（如 \\?\UNC\Server\Share）。绕过 Win32 API 的 260 字符限制，直通 NT 内核（支持 32,767 字符）。

4.2 符号链接与死循环阻断

    重解析点识别：读取文件属性，检测 FILE_ATTRIBUTE_REPARSE_POINT 标志。
    默认不跟随：扫描与提取阶段，遇到该标志直接视为单文件处理，拒绝递归进入，100% 物理防死循环。
    安全跟随模式（高级选项）：若用户强开，需引入 FileId (Inode) 哈希表。每次进入真实目录前校验 FileId，发现重复则判定为物理回环，立刻斩断当前分支。

4.3 大小写冲突防御

    暗坑场景：从 Linux/Mac 拷贝来的 File.txt 与 file.txt 在 Windows 下共存，常规移动会导致后者静默覆盖前者。
    防御策略：在执行移动/复制 IO 前，强制对目标目录现有文件执行不区分大小写的名称比对。若存在逻辑重名，直接触发“冲突重命名”流程。

5. 高级权限与网络文件处理规范
5.1 动态提权机制

    默认行为：遇到权限拒绝（Error 5），直接跳过并标记为 Status: Locked。
    JIT 提权流程（需用户显式触发）：
        任务队列遇到 Locked 文件时挂起。
        UI 弹窗警告：“发现受保护文件，是否尝试强制获取所有权？”
        用户确认后，调用 ShellExecute 申请 UAC 提权（或提示重启软件）。
        底层调用 Win32 API SetPrivilege 启用 SE_TAKE_OWNERSHIP_NAME 特权。
        调用 SetNamedSecurityInfo 将文件所有者改为当前用户，并赋予 FULL_CONTROL。
        执行文件操作，完成后继续队列。

5.2 网络文件系统 (UNC/NAS) 优化

    禁用预检测：网络环境下，严禁在移动前调用 File.Exists 进行存在性校验（会产生巨大的网络延迟）。采用“直接移动，捕获异常再处理”的激进策略。
    断网容错：捕获 ERROR_BAD_NETPATH 等特定网络异常。若发生，不将文件标记为彻底失败，而是将当前处理队列挂起，UI 弹出“网络连接中断，请检查后重试”，保留恢复上下文的能力。

6. UI/UX 交互状态映射

底层极其复杂的逻辑，在界面上必须表现为极简的状态机：

    预览期（Dry Run）：所有操作默认为预览模式，生成《预期变更影响清单》（列出将删除、移动、重命名的文件清单），用户点击“确认执行”才触发底层 IO。
    运行期：
        进度条：反映“已处理文件数/总预估文件数”（遇到错误进度条照常前进，不卡顿）。
        实时日志窗：仅滚动打印 Warning（黄色，如跳过系统文件）和 Error（红色，如无权限），正常文件不打印防刷屏。
    完成期：弹窗汇总：“成功处理 8500 项，跳过/失败 12 项”。提供 “导出错误诊断报告” 按钮，输出结构化 JSON 供高级用户排查。
