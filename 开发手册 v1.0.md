## 一、 技术栈与依赖约束
### 1.1 运行时依赖
| 包 | 版本 | 用途 |
|:--|:--|:--|
| `tqdm` | ≥ 4.60 | 终端进度条底层驱动 |
| `colorama` | ≥ 0.4.4 | Windows 终端 ANSI 转义序列支持 |
### 1.2 标准库重度使用
本工具坚持“零外部逻辑依赖”原则，底层实现完全依赖以下标准库模块：
`pathlib`, `shutil`, `hashlib`, `os`, `sys`, `re`, `json`, `argparse`, `logging`, `dataclasses`, `threading`, `concurrent.futures`, `time`, `uuid`, `math`, `typing`.
### 1.3 工程底线（不可违背）
1. **Copy-Only 原则**：全局代码中**严禁**出现对源目录的 `os.remove`, `os.rename`, `shutil.move`。只能使用 `shutil.copy2`。
2. **原地修改原则**：绝不修改源文件的任何元数据（包括时间戳，即使复制失败也不要去碰源文件）。

## 二、 核心数据结构
这是整个系统流转的“血液”，所有模块间的交互必须严格基于以下数据类。
### 2.1 文件树节点 (`FileNode`)
```python
from dataclasses import dataclass, field
from pathlib import Path
from typing import List, Optional
@dataclass
class FileNode:
    """文件系统在内存中的单向树镜像"""
    name: str                           # 文件/文件夹名称
    absolute_path: Path                 # 源目录中的绝对路径
    is_file: bool                       # True=文件, False=文件夹
    file_size: int = 0                  # 字节数，仅 is_file=True 时有效
    
    # 树结构
    children: List['FileNode'] = field(default_factory=list)
    parent: Optional['FileNode'] = field(default=None, repr=False)
    
    # --- 算法运行时动态字段 (由 Scanner 或 Penetrator 填充) ---
    sw: int = 0                         # 穿透深度 (shells_walked)
    is_valid: bool = True               # 是否有效（内部是否含非系统文件）
    tier: int = 0                       # 判定档位 (0=未判定, 1=纯空壳, 2=分支, 3=单文件叶, 4=文件型)
    ancestry_chain: List[str] = field(default_factory=list) # 穿透血统链（用于溯源重命名）
```
### 2.2 重构映射条目 (`MapEntry`)
```python
@dataclass
class MapEntry:
    """表示一个从源到目标的文件复制动作"""
    source_path: Path                   # 源绝对路径
    target_path: Path                   # 目标绝对路径
    file_size: int = 0                  # 用于断点续传判断
    
    # 状态标记
    action: str = "COPY"                # "COPY" | "SKIP"
    skip_reason: Optional[str] = None   # "duplicate" | "empty" | "system_file"
    rename_reason: Optional[str] = None # "conflict:溯源于[A]"
    duplicate_of: Optional[Path] = None # 如果是重复文件，指向保留的那个文件的源路径
```

## 三、 核心算法实现规范
### 3.1 平台感知的字符串比较
由于 Windows 文件系统不区分大小写，**所有涉及节点名称比较的地方，必须使用 `.lower()` 或 `casefold()`**。
```python
def are_names_equal(name1: str, name2: str) -> bool:
    return name1.lower() == name2.lower()
```
### 3.2 穿透判定器 主流程
```python
def resolve_node(node: FileNode, sw: int = 0, chain: List[str]) -> List[MapEntry]:
    """
    递归处理一个节点，返回该节点及其子树最终应该产出的 MapEntry 列表。
    """
    # Step 1: 过滤系统文件，计算有效内容
    valid_files = [f for f in node.children if f.is_file and not is_system_file(f.name)]
    valid_dirs = [d for d in node.children if not d.is_file and d.is_valid]
    f_count, d_count = len(valid_files), len(valid_dirs)
    
    entries = []
    
    # Step 2: 四档分流
    if f_count == 0 and d_count == 1:
        # 第一档：纯空壳 -> 消失，传递给唯一子节点
        new_chain = chain + [node.name]
        return resolve_node(valid_dirs[0], sw + 1, new_chain)
        
    elif f_count == 0 and d_count >= 2:
        # 第二档：分支型终点
        if sw > 0:
            # 穿透而来的分支，原样保留为文件夹，内部子项以 sw=0 重新判定
            entries.extend(_process_children_as_dir(node, valid_dirs, valid_files, chain))
        else:
            # 原生分支，触发同生共死检查
            entries.extend(_co_extract_and_resolve(node, valid_dirs, valid_files, chain))
            
    elif f_count == 1 and d_count == 0:
        # 第三档：单文件叶 -> 强制提取
        file_node = valid_files[0]
        target_name = file_node.name
        # 注意：提取出的文件携带 chain，将在上层统一进行冲突检查
        entries.append(MapEntry(
            source_path=file_node.absolute_path, 
            target_path=Path(target_name), # 临时相对路径，后续由 Renamer 修正
            file_size=file_node.file_size,
            _pending_chain=chain,           # 内部临时字段，传递给重命名器
            _pending_parent=node            # 内部临时字段
        ))
        
    elif f_count >= 1:
        # 第四档：文件型终点
        if sw > 0:
            entries.extend(_process_children_as_dir(node, valid_dirs, valid_files, chain))
        else:
            entries.extend(_process_children_as_dir(node, valid_dirs, valid_files, chain))
            
    return entries
```
### 3.3 同生共死机制 (`_co_extract_and_resolve`)
```python
def _co_extract_and_resolve(node, valid_dirs, valid_files, chain):
    entries = []
    extract_pool = []
    
    # 收集所有 sw=0 的第四档子文件夹（实际实现中需要先预判子项的 tier）
    # 简化伪代码逻辑：
    for d in valid_dirs:
        if is_single_file_endpoint(d): # 预判：里面只有一个文件
            extract_pool.append(d.get_single_file())
            
    # 判定是否全部提取
    can_extract = len(extract_pool) > 0 and all(is_single_file_endpoint(d) for d in valid_dirs)
    
    if can_extract:
        # 全部提取，这些文件携带 chain，等待上层冲突检查
        for f_node in extract_pool:
            entries.append(MapEntry(source_path=f_node.absolute_path, ...))
    else:
        # 不提取，原样保留
        entries.extend(_process_children_as_dir(node, valid_dirs, valid_files, chain))
        
    return entries
```
### 3.4 统一溯源前缀法 (`resolve_conflicts`)
在 `resolve_node` 返回的 entries 列表中，同一层级（同一个父节点下）可能出现同名项。必须在转换为绝对路径前调用此函数。
```python
def resolve_conflicts(entries: List[MapEntry]) -> List[MapEntry]:
    # 按 target_path.name (不区分大小写) 分组
    groups = group_by_case_insensitive_name(entries)
    
    final_entries = []
    for name, group in groups.items():
        if len(group) == 1:
            final_entries.extend(group)
            continue
            
        # 冲突发生，两两溯源
        for entry in group:
            chain = entry._pending_chain
            other_chains = [e._pending_chain for e in group if e != entry]
            
            ancestor_prefix = find_first_different_ancestor(chain, other_chains)
            
            # 清洗祖先名称（去非法字符）
            safe_prefix = sanitize_filename(ancestor_prefix)
            
            # 拼接新名称
            if entry.is_file: # 这里需要在MapEntry中标记是否原为文件
                base, ext = os.path.splitext(entry.target_path.name)
                new_name = f"{safe_prefix}-{base}{ext}"
            else:
                new_name = f"{safe_prefix}-{entry.target_path.name}"
                
            # 二次清洗（防截断、防空名称）
            entry.target_path = Path(sanitize_filename(new_name))
            entry.rename_reason = f"conflict:溯源于[{ancestor_prefix}]"
            
        final_entries.extend(group)
        
    return final_entries
def find_first_different_ancestor(my_chain: List[str], other_chains: List[List[str]]) -> str:
    for i, my_name in enumerate(my_chain):
        for other_chain in other_chains:
            if i >= len(other_chain) or not are_names_equal(my_name, other_chain[i]):
                return my_name
    return my_chain[-1] # 极端情况兜底
```

## 四、 增强模块实现规范（吸收最佳实践）
### 4.1 四级哈希去重引擎 (`DuplicateDetector`)
吸收业界成熟方案，替代简单的部分哈希，专门针对大量混合文件（尤其是大视频文件）优化。
**四级过滤漏斗**：
```python
class DuplicateDetector:
    def detect(self, entries: List[MapEntry]) -> List[MapEntry]:
        # 第一级：大小分组 (O(N) 极快)
        size_groups = group_by_size(entries)
        
        # 第二级：快速哈希 (仅读取 192KB)
        # 采样点：前 64KB + 文件正中间 64KB + 倒数前 64KB
        quick_hash_groups = {}
        for size, group in size_groups.items():
            if size == 0 or len(group) < 2: continue
            for entry in group:
                q_hash = self._get_quick_hash(entry.source_path, size)
                quick_hash_groups.setdefault(q_hash, []).append(entry)
                
        # 第三级：完整 SHA-256 (仅对快速哈希相同的文件执行，数量极少)
        final_groups = {}
        for q_hash, group in quick_hash_groups.items():
            if len(group) < 2: continue
            for entry in group:
                f_hash = self._get_full_sha256(entry.source_path)
                final_groups.setdefault(f_hash, []).append(entry)
                
        # 第四级：根据策略 (keep_first / keep_largest) 标记 SKIP
        return self._apply_strategy(final_groups, entries)
    def _get_quick_hash(self, path: Path, total_size: int) -> str:
        chunk_size = 64 * 1024 # 64KB
        h = hashlib.md5()
        with open(path, 'rb') as f:
            # 头部
            h.update(f.read(chunk_size))
            # 中间 (计算偏移量)
            if total_size > chunk_size * 2:
                mid_offset = (total_size - chunk_size) // 2
                f.seek(mid_offset)
                h.update(f.read(chunk_size))
            # 尾部
            f.seek(-chunk_size, 2)
            h.update(f.read(chunk_size))
        return h.hexdigest()
```
### 4.2 磁盘感知调度器 (`DiskAwareScheduler`)
吸收“SSD/HDD 自动调优”思路，防止在机械硬盘上开多线程导致系统卡死。
```python
import subprocess
class DiskAwareScheduler:
    def __init__(self, target_dir: Path):
        self.disk_type = self._detect_disk_type(target_dir)
        self._apply_tuning()
        
    def _detect_disk_type(self, target_dir: Path) -> str:
        """检测目标目录所在磁盘是 SSD 还是 HDD"""
        try:
            # 获取目标盘符，如 'C:'
            drive = str(target_dir.resolve().anchor)
            # 通过 wmic 查询 MediaType (1=SSD/NVMe, 2=HDD)
            cmd = f"wmic diskdrive get MediaType, DeviceID"
            output = subprocess.run(cmd, shell=True, capture_output=True, text=True).stdout
            
            # 简化匹配逻辑：如果关联的磁盘设备包含 "SSD" 或 "NVMe" 或 MediaType 为 1
            if "SSD" in output.upper() or "NVME" in output.upper():
                return "SSD"
        except Exception:
            pass
        return "HDD" # 默认按最安全的 HDD 处理
    def _apply_tuning(self):
        if self.disk_type == "SSD":
            self.max_workers = 16
            self.throttle_delay_ms = 20
        elif self.disk_type == "HDD":
            self.max_workers = 2  # 机械硬盘极度害怕随机寻道
            self.throttle_delay_ms = 100
        else:
            self.max_workers = 4
            self.throttle_delay_ms = 50
```
### 4.3 容错型沙箱复制器 (`SandboxCopier`)
吸收“IO 重试机制”和“轻量级锁文件”，保障长时间运行的稳定性。
**1. IO 重试装饰器**：
```python
import time
import shutil
from functools import wraps
def io_retry(max_retries=3, delay=0.5):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            last_exc = None
            for attempt in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except (OSError, PermissionError) as e:
                    last_exc = e
                    # Windows 特有：杀毒软件扫描锁定
                    if attempt < max_retries - 1:
                        time.sleep(delay)
            # 重试耗尽，记录为失败但不中断程序
            logging.error(f"IO 操作失败，已达最大重试次数: {args[0]} | 错误: {last_exc}")
            return False 
        return wrapper
    return decorator
@io_retry(max_retries=3, delay=0.5)
def safe_copy(src: Path, dst: Path):
    # 原子性写入：先写临时文件
    tmp_dst = dst.with_suffix(dst.suffix + '.nesttidy_tmp')
    shutil.copy2(src, tmp_dst)
    tmp_dst.rename(dst) # rename 在同一分区是原子操作
```
**2. 进程级防并发锁**：
```python
import json
import atexit
from pathlib import Path
class ProcessLock:
    def __init__(self, target_dir: Path):
        self.lock_file = target_dir / ".nesttidy.lock"
        
    def acquire(self):
        if self.lock_file.exists():
            raise RuntimeError("目标目录已被其他理巢进程锁定。如确需执行，请手动删除 .nesttidy.lock")
        with open(self.lock_file, 'w') as f:
            json.dump({"pid": os.getpid(), "time": time.time()}, f)
        atexit.register(self.release) # 进程异常退出时自动清理
        
    def release(self):
        if self.lock_file.exists():
            self.lock_file.unlink()
```

## 六、 Windows 特殊边界处理规范
除了常规的 `NameSanitizer` 处理 `<>:"/\|?*` 外，开发时必须显式处理以下 Windows 阵痛：
| 问题 | 处理策略 |
|:--|:--|
| **路径超长 (>260字符)** | 在 Python 脚本入口处，**强制**添加 `os.path.abspath(__file__)` 级别的长路径前缀标记，或显式调用 `ctypes.windll.kernel32.SetDllDirectoryW(None)` 以解除 `MAX_PATH` 限制。 |
| **文件被杀毒软件锁定** | 统一使用 `@io_retry` 装饰器。重试 3 次仍失败则记入 `errors.log`，**绝不弹窗报错阻断主流程**。 |
| **权限不足 (ACL问题)** | Scanner 阶段遇到无权限，`try...catch PermissionError`，将该目录标记为无效并记日志。 |
| **符号链接/Junction** | 默认**跟随**符号链接读取内部文件。但在统计大小时，不计入符号链接本身的大小（避免死循环或重复计算）。 |
| **保留名称** | `CON`, `PRN`, `AUX`, `NUL`, `COM1` 等，在 `NameSanitizer` 中强制替换为 `_CON_` 等。 |
